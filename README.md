# Сервис доставки заказов

## Назначение

Веб-сервис для приёма и доставки заказов от клиентов до двери. Приложение
автоматизирует оформление заказа, расчёт стоимости и срока доставки, назначение
курьера и отслеживание статуса заказа. Решает задачу связывания трёх сторон
процесса - клиента, оператора сервиса и курьера - в едином рабочем пространстве.

## Целевая аудитория

- **Клиенты** - частные пользователи, которые оформляют доставку товаров или еды
  на дом либо в офис.
- **Курьеры** - сотрудники и самозанятые исполнители, принимающие заказы в работу.
- **Операторы (диспетчеры) сервиса** - сотрудники, контролирующие очередь заказов,
  назначение курьеров и разбор проблемных ситуаций.

## Предметная область

Предметная область - логистика доставки «последней мили». Клиент формирует заказ
с адресом и составом, сервис рассчитывает стоимость доставки в зависимости от зоны
и веса, подбирает курьера подходящего типа (пеший, велокурьер, автокурьер),
оценивает время прибытия и ведёт заказ по статусам от оформления до вручения.

## Основные сущности

- **Клиент** - имя, телефон, адрес доставки, история заказов.
- **Заказ** - номер, клиент, состав, сумма товаров, вес, адрес, статус, время создания.
- **Курьер** - имя, тип передвижения, статус занятости, текущий заказ, рейтинг.
- **Доставка** - заказ, назначенный курьер, стоимость доставки, зона, плановое и
  фактическое время вручения.
- **Зона доставки** - название, базовый тариф, ориентировочное время в пути.

## Основные функции

1. **Оформление заказа** - приём данных клиента и заказа, определение зоны доставки,
   расчёт стоимости доставки с учётом веса и порога бесплатной доставки, подсчёт
   итоговой суммы к оплате.
2. **Назначение курьера** - подбор типа курьера по весу заказа и проверка режима
   работы сервиса, фиксация исполнителя за заказом.
3. **Расчёт срока доставки** - оценка планового времени вручения на основе времени
   на сборку заказа и времени в пути по выбранной зоне.
4. **Отслеживание статуса заказа** - перевод заказа по цепочке статусов
   (создан → подтверждён → у курьера → доставлен / отменён) и вывод текущего статуса.
5. **Формирование квитанции** - вывод итоговой квитанции по заказу с номером для
   отслеживания, составом расчёта и плановым временем доставки.

## Реализованные функции (ПР2)

На этапе ПР2 начальный сценарий ПР1 доработан до консольного
приложения, работающего с множеством заказов и курьеров:

1. **Оформление заказа** - ввод данных клиента и заказа, определение
   зоны доставки, расчёт стоимости с учётом веса и порога бесплатной
   доставки, автоматическое назначение свободного курьера подходящего
   типа, вывод квитанции.
2. **Учёт курьеров** - список курьеров с типом передвижения и признаком
   занятости; поиск свободного курьера и освобождение после отмены
   заказа.
3. **Поиск и фильтрация** - поиск заказов по имени или телефону
   клиента, отбор заказов по зоне доставки.
4. **Сортировка** - сортировка заказов по расстоянию, весу или сумме
   товаров с использованием lambda-функций в качестве ключа.
5. **Статистика** - подсчёт выручки, среднего чека и количества
   активных заказов по зонам доставки.
6. **Отмена заказа** - отмена заказа с освобождением назначенного
   курьера.
7. **Хранение данных** - заказы и курьеры сохраняются в JSON-файлах и
   загружаются при следующем запуске программы.
8. **Обработка ошибок** - некорректный ввод пользователя и повреждённые
   или отсутствующие файлы данных не приводят к аварийному завершению
   программы.

## Объектная модель (ПР3)

На этапе ПР3 функциональная модель ПР2 (словари + функции) переработана
в объектную: основные сущности стали классами, коллекции словарей -
коллекциями объектов `list[Customer]`, `list[Courier]`, `list[Order]`.

### Customer - клиент

Атрибуты: `id`, `name`, `phone`.

Методы:
- `from_data()` (`@classmethod`) - создание клиента из данных JSON;
- `matches(query)` - есть ли подстрока в имени или телефоне;
- `__str__()` - строковое представление.

### Courier - курьер

Атрибуты: `id`, `name`, `type` (пеший курьер / велокурьер / автокурьер),
`is_free` - свойство только для чтения (`@property`) над закрытым
атрибутом `_is_free` (инкапсуляция: занятость меняется только методами).

Методы:
- `from_data()` (`@classmethod`) - создание курьера из данных JSON;
- `is_suitable_for(weight)` - подходит ли курьер по типу для веса заказа;
- `take_order()` / `release()` - принять заказ / освободиться;
- `__str__()` - строковое представление с признаком занятости.

### Order - заказ

Атрибуты: `id`, `customer` (объект `Customer`), `courier` (объект
`Courier` или `None`), `distance_km`, `weight`, `goods_sum`,
`payment_is_online`, `created_at` (`datetime`), `is_cancelled`.

Методы и свойства:
- `validate_amount()` (`@staticmethod`) - проверка неотрицательности
  расстояния, веса и суммы;
- `zone`, `status` (`@property`) - зона доставки и текущее состояние;
- `delivery_cost()`, `total_to_pay()`, `delivery_minutes()`,
  `planned_delivery_at()`, `tracking_number()` - расчёты по заказу;
- `assign_courier(courier)` - закрепить курьера за заказом;
- `cancel()` - отменить заказ и освободить курьера;
- `__str__()` - строковое представление.

### Взаимодействие объектов

```
Order
 ├── customer → Customer   (кто заказал)
 └── courier  → Courier    (кто везёт, может отсутствовать)
```

- `create_order()` создаёт объект `Order`, ищет свободного курьера
  подходящего типа (`Courier.is_suitable_for()`) и закрепляет его через
  `Order.assign_courier()` → `Courier.take_order()`.
- Курьер, занятый активным заказом, не назначается на новый заказ.
- `cancel_order()` находит заказ и вызывает `Order.cancel()`, который
  освобождает курьера (`Courier.release()`). Отменённый заказ остаётся
  в коллекции, повторная отмена не выполняется.

Тарифные функции ПР1 (`delivery_zone()`, `zone_base_price()`,
`weight_surcharge()` и др.), функции работы с коллекциями (поиск,
сортировка, фильтрация, статистика), функции хранения и ввода остались
обычными функциями: это правила сервиса и операции над наборами
объектов, а не поведение одного объекта.

```
│   ├── test_orders.py

```

## Формат данных

Клиенты (`data/customers.json`): `id`, `name`, `phone`.

Курьеры (`data/couriers.json`): `id`, `name`, `type`, `is_free`.

Заказы (`data/orders.json`): `id`, `customer_id`, `courier_id`
(`null`, если курьер не назначен), `distance_km`, `weight`, `goods_sum`,
`payment_is_online`, `created_at` (ISO 8601), `is_cancelled`.

В JSON хранятся идентификаторы связанных объектов. При загрузке
`storage.py` находит по `customer_id` / `courier_id` объекты `Customer`
и `Courier` и передаёт их в конструктор `Order`; заказ с несуществующим
клиентом или курьером пропускается с предупреждением. При сохранении
ссылки на объекты заменяются их идентификаторами.

## Запуск

Создание виртуального окружения и установка зависимостей для
разработки (pytest, flake8):

```
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запуск приложения:

```
python main.py
```

Запуск автоматизированных тестов:

```
pytest -v
```

Тесты проверяют создание объектов и их атрибуты, строковое
представление, методы классов, связь заказа с клиентом и курьером,
правило занятости курьера (занятый курьер не назначается, после отмены
заказа освобождается), поиск, сортировку, статистику, а также
сохранение объектов в JSON и восстановление связей при загрузке.

Проверка качества кода линтером:

```
flake8
```

## План развития

На следующих этапах планируется:

- разработка веб-приложения на Django;
- подключение базы данных и ORM для хранения заказов, клиентов и курьеров;
- реализация пользователей, регистрации и разграничения доступа (клиент / курьер / оператор);
- разработка REST API для мобильного приложения курьера;
- контейнеризация приложения в Docker;
- настройка CI/CD и автоматизированного тестирования.
